- estamos criando um addon feito em gdscript puro e sem dependencias para a game engine godot na versao 4.7.2 que implementa um transpilador lisp, que recebe como entrada um texto lisp ou um path de um arquivo de texto lisp e gera como saida uma string que poderia ser salva em um arquivo gdscript valido
- este transpilador é meramente sintatico, ele nao valida semantica, não assume nada sobre runtime e nem pode ser interpretado ou ter recursos de runtime, é apenas um transpilador sintatico extensivel por meio de macros.
- as responsabilidades do transpilador devem ser separadas em classes RefCounted diferentes, em arquivos diferentes. uma classe para o tokenizer, outra que converte a lista simples de tokens em uma arvore aninhada de listas, outra que faz a transpilacao e qualquer outra que for necessaria entre elas.
- nao existem "tipos de dados" nas listas além de strings e listas. o transpilador vai meramente trabalhar com uma tabela de operacoes com nomes pre-conhecidos e realizar as transformacoes baseado nas operacoes.
- strings nao precisam estar entre aspas a menos que contenham whitespace ou caracteres, abre parenteses, fecha parenteses, backslash ou os caracteres delimitadores de string.
- strings podem ser "empacotadas" com os seguintes caracteres delimitadores: aspas duplas ("), simples ('), grave acent (`) ou acute acent (´). estes caracteres nao podem ser misturados (se comecou com um, tem que terminar com ele). usamos 4 diferentes pra permitir que o usuario possa empacotar um texto contendo os outros sem problemas. entretanto deve ser sempre permitido escapar um desses caracteres dentro da string usando backslash (\). e como backslash é um caractere de escape, pra digitar um dentro de uma string precisamos escapar ele com outro backslash.
- o transpilador deve permitir a inclusao de outros arquivos atraves de um path relativo ao arquivo atual, absoluto em relacao ao projeto (res://) ou absoluto em relacao ao sistema (/). em sistemas windows paths comecados em / devem receber o prefixo "/c:".
- o transpilador deve permitir a definicao de macros, deve permitir que macros sejam utilizadas dentro de outras macros, e deve permitir que as macros sejam desdobradas etapa por etapa até chegar em uma estrutura final (antes da transpilacao para gdscript) que não contenha mais macros nao desdobradas.
- devem haver guardas de segurança contra macros recursivas entre si e desdobramentos infinitos de macros, como por exemplo definir uma quantidade maxima de desdobramentos antes de acusar um erro e abortar a rotina.
- vamos criar as funcionalidades de forma incremental, lentamente, uma de cada vez, sempre testando e validando tudo a cada etapa.
